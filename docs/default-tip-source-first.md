# Default-tip source-first prototype

`python3 -m tools.default_tip_event CURRENT_CHECKPOINT CURRENT_INDEX PRIOR_CHECKPOINT PRIOR_INDEX RUN_DIR` independently rechecks a selected pending v3 default-tip decision through fixed GitHub metadata, commit/tree and a fresh canonical branch fetch. The control candidate is a selected prior observation for the same repository and branch with a strictly earlier observation time, a distinct commit and an independently fetched matching tree. This does not establish that the earlier observation was the immediate previous tip, that checkpoint history is authentic, or that the control is clean. Both source and control checkouts fetch the digest-pinned v0.6 policy commit for the next step. A new run directory is required.

`python3 -m tools.default_tip_manifest RUN_DIR/identity-receipt.json RUN_DIR OUTPUT_DIR` checks the exact identities and checkout cleanliness, compares each independently against the frozen policy commit, and prepares separate source-derived inventories and manifests with binding digests. Changed candidates, routes or reviewed recipe/config inputs fail closed under the existing selector and oracle. Other repositories remain at policy pins. The policy records reviewed source projections, not verified installed package bytes. No CodeQL execution, SARIF, clean-control assertion, discovery authenticity, durable queue completion or Gate 8 result is established. Output can be partially written when a later control check fails; only a complete binding indicates both oracle preparations completed.

Tests are offline: `python3 -B -m unittest tools.test_default_tip_manifest tools.test_default_tip_event policy.tests.test_incoming_event tools.test_event_corpus_manifest -q`. They use synthetic Git histories and policy fixtures; they are not a live upstream or released-producer handoff.
