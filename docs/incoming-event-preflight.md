# Incoming event identity preflight

This workflow is a bounded `workflow_dispatch` drill for resolving an open
OpenWrt or LuCI PR and a clean control revision. It fetches and retains the
exact GitHub pull API response, checks the response's PR number, open state,
base repository, head repository identity, fork flag and full head SHA against
the dispatch's explicit expected `source_sha`, then
checks out `refs/pull/<number>/head` from the canonical base repository. This
supports fork PRs without trusting a caller-supplied source repository URL.
The resolver requires the fetched PR ref's HEAD to equal the API head SHA and
the control checkout's clean HEAD to equal its full input SHA; both tree SHAs
are recorded. The control revision is always checked out from canonical
upstream.

The receipt status is deliberately `identities_resolved_only`. The API
response is retained as the source of truth for PR membership; the run
timestamp is generated by the workflow. The workflow also compares the PR head against the exact `base.sha` from the
captured API response using the checked-in, digest-pinned v0.4 source policy.
It fetches that full base commit into the shallow PR checkout and records base
and event tree identities in the drift report. The same job then inventories
tracked Ucode candidates at both commits against the digest-pinned v0.6
source policy. It retains `full-tree-candidates.json` with selected, excluded
and unreviewed identities, and fails closed on additions, removals, changed
signals, changed exclusions and unresolved candidates. These comparisons do
not infer install recipes or full source coverage, invoke the released
producer, or pass SARIF to the consumer. They do not establish Gate 8 or
security behavior.
The following [source-first event corpus oracle](event-corpus-manifest.md)
refreshes selected Git blobs and hashes from the verified head and checks
routes before extraction. It remains an input contract for a later released
scanner job.
On changes to the workflow, selector, resolver, tests or v0.6 manifest, a
separate pull-request contract job runs the resolver and selector controls.
It does not fetch upstream source or execute the manual drill.
Do not turn this preflight into blocking incoming CI until those steps have a
reviewed implementation and a live end-to-end drill.

Run the mechanical tests with:

```sh
python3 -B -m unittest policy.tests.test_incoming_event -v
python3 -B tools/test_full_tree_candidates.py -v
python3 -B -m unittest tools.test_event_corpus_manifest -v
```

The tests use temporary local Git repositories and mocked pull API JSON; they
do not access GitHub.
