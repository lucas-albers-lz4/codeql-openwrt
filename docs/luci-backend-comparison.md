# Bounded LuCI declaration / grant comparison

`python3 -m policy.backend_declarations` is a non-writing, offline validator and
reporter. It accepts the eight-column table decoded from
`ql/src/m4/LuciBackendDeclarations.ql`, separately decoded
`SuccessfullyExtractedFiles` and `ExtractionErrors` CSVs, and the absolute,
canonical source root used for extraction. It checks exact source bytes,
diagnostic paths and row shapes, the consumer-owned source multiset, the pinned
lock/profile/catalog bytes, and the full pinned grant-identity map. It writes
UTF-8 JSON to stdout only; validation errors return nonzero on stderr and no
success payload. It neither runs CodeQL nor writes grants, findings, effects or
coverage. Empty or unsupported extraction is an error/unknown.

For already decoded files from a separately captured run, use explicit paths:

```sh
python3 -m policy.backend_declarations \
  --table "$TABLE_CSV" --extracted "$EXTRACTED_CSV" \
  --errors "$ERRORS_CSV" --source-root "$ABSOLUTE_SOURCE_ROOT" \
  > "$EXPLICIT_REPORT_PATH"
```

The source root must contain `usr/share/rpcd/ucode/luci`; the success CSV's
`f` column must equal that absolute file path, with an empty `col1`. The errors
CSV must contain exactly its expected header and no rows. Independently capture
and retain the real routing receipt, query and decode commands, exit statuses,
raw BQRS/CSV and context if claiming a real handoff. This comparator does not
verify those process receipts, producer revision, query execution or freshness.
Its producer/query and consumer-baseline fields are references, not attestations.
Hashes and matching deterministic output alone cannot establish execution.

## Retained offline comparison

`reports/luci-backend-declaration-comparison.json` was generated by the CLI
from the unchanged historical `table.csv` below and the consumer's pinned
source and catalog, with **synthetic** success/error diagnostics bound to a
newly staged copy of the source. It is a regression artifact, not a fresh
producer extraction or a paired handoff. It contains 21 declaration identities,
18 represented methods, and 38 existing grant IDs; `getInitList`,
`getUSBDevices`, and `setInitAction` have no current grant row. That relation
is not a denial, ACL defect, reachability, runtime registration, coverage or
security assessment. Existing coverage includes `setInitAction`, so only the
first two names are absent from the preexisting grants/effects-derived ledger.

`policy/tests/fixtures/backend-declarations-historical/` preserves the raw
historical table, diagnostic CSVs, BQRS, routing receipt and original SHA-256
list without rewriting their bytes. They came from the earlier local
`backend-83-final-evidence` producer smoke artifact; its absolute source root
was removed by that smoke. Its diagnostics therefore cannot be presented as
from this offline report's newly staged source. The retained source hash in the
original list is a historical assertion, not a read-boundary observation of
the deleted path. The earlier producer smoke's query plans used a cache; the
identical table digest does not identify which query bytes executed. No claim is
made that this historical artifact was produced by merged commit d54c17a.

The provisional consumer source fixture `policy/tests/fixtures/luci-backend-source-v1.json`
was made by inspecting the pinned source fixture's direct methods region: key
lines, `call: function` starts and function-closing lines were transcribed using
a pin-specific indentation scan (not a general ucode parser). The author had
also seen the producer's table and the prior assessment; this is **not blinded
independent review**. A separate source-first review must compare the fixture
before it is treated as independently approved. The grant fixture snapshots
identity/context fields from the current materialized catalog; it is not an
independent ACL correctness oracle. Both fixtures are pinned by byte digest in
the comparator; updates require deliberate code and fixture review.

## Verification / future handoff

```sh
python3 -m unittest policy.tests.test_backend_declarations -v
python3 -O -m unittest policy.tests.test_backend_declarations -v
python3 -m unittest discover -s policy/tests -t . -v
```

A future paired handoff must separately pin the committed consumer, merged
producer, actual source and query bytes, lock, profile, grants and both oracles;
use fresh isolated extraction/output roots and capture actual init, index,
routing, finalize, query and decode receipts. Run this CLI on those exact decoded
files with the same source root and retain raw results and bounded provenance.
The offline report and its tests are not that handoff and cannot satisfy the
issue's real-extraction acceptance gate by themselves.
