`receipts/` contains per-stage stdout, stderr, exit statuses and the actual shell trace, where present. Separate files remain separate; no merged transcript substitutes for output bytes. `capture/launch.json` binds the observed launch return code/timing and parent supervisor results. `capture/approval-and-inventory.json` binds the external parent approval digest, approval-context digest, input inventory identifiers and before/after checks. `capture/phase-status.json` lists actual phase exits. ## Reproduction/verification

To verify the portable export, run `sha256sum -c SHA256SUMS` from this directory. `capture/artifact-digests.json` links each redacted published file to its original raw SHA-256; for omitted `extracted.bqrs`, it records only the original SHA-256/size and an explicit omission reason. `capture/published-bqrs-verification.json` records the read-only CodeQL 2.27.4 checks: the published errors/table BQRS both decode successfully and their decoded CSV bytes equal the published CSVs; the original extracted BQRS decodes successfully, and only its decoded CSV path token is then redacted to match the published sanitized CSV. No synthetic BQRS was generated or published. The full original raw extracted BQRS remains in the external execution attempt, unchanged, but is not part of this repository export. Independently review `audit/summary.md` and `audit/verified-outcomes.json`; they summarize the separate actual-run audit, rather than generating outputs. The launch timestamp, recipe hash, recipe-block hash, approved consumer commit and producer merge/tree relationship are recorded in the metadata. No full database, dependencies, compilation caches, source archive, full input inventories, or complete private scratch capture is copied.
