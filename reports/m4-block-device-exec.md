## Selected scope, assumptions, and limits

The producer selects a file named `luci`, syntactic containment in a recognized `setBlockDetect: { call: function(...) { ... } }`, a `BuiltinSystemCall`, exactly one argument, and the exact literal `/sbin/block detect > /etc/config/fstab`. The selected consumer case is one byte-pinned installed source and one exact observation. This is a source-syntax observation with `partial` coverage, not proof that the callback is registered, invoked, reachable from a request, or executed.

Builtin `system` classification is a shared syntactic lexical-binding approximation: imports, formals and visible declarations named `system` are excluded, but global rebinding, alias semantics and runtime target identity are not established. Syntactic ancestry may include nested function bodies; it does not prove that a nested function is called or a callback is registered. The source call does not establish `intended_access`: the primary mounts grant is joined to the independent synthetic mounts expectation (`expectation_id` `luci-mod-system-mounts`), and the supplementary root grant is separately joined to `root-administration`. These aggregate joins do not transfer the mounts assessment to root callers. Unauthenticated has no grant and the existing `policy:decision:unauthenticated-setBlockDetect-deny` remains intact.

Other methods, commands, files and profiles; arbitrary nonliteral commands; member/receiver/wrapped/aliased callees; interprocedural flow, CFG/SSA, taint or sanitizer proofs; callback registration; live uhttpd/rpcd or firmware execution; exploitability and authorization violations are outside this family. Do not close broader #64 or producer #54/#55 from this selection. The sibling `setLocaltime` inventory row remains relevant historical coverage but is not part of this selected family.
