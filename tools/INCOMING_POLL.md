# Incoming discovery prototype

This read-only prototype inventories observed OpenWrt and LuCI open PR heads and default-branch tips. It does not scan, dispatch, schedule, or establish Gate 8. Run only as a manual experiment with network access and a new run-owned output directory:

```
python3 -B tools/incoming_poll.py --genesis --capacity 2 --output-dir /path/to/new/run
python3 -B tools/incoming_poll.py --previous /path/to/prior/decisions.json --capacity 2 --output-dir /path/to/another/new/run
```

`GITHUB_TOKEN` is optional; use a short-lived token with public-repository read access only. API calls are read-only. Exact response bytes (base64), digests and response metadata are retained in the decision record; failures retain the successfully captured requests and, for HTTP errors, the attempted path, status, bounded response-prefix digest, selected safe GitHub message, request ID and rate headers. Arbitrary server text and authorization headers are omitted. Failures never produce a checkpoint. A fresh genesis explicitly abandons prior observation history. Operators must retain and supply the immediately preceding successful record; this prototype has no durable cross-run store or protection against rollback. Do not schedule it until durable append-only state, recovery and ownership are designed and reviewed.

Pending records survive later head changes or disappearance, and capacity limits selection rather than discarding backlog. A 10,000-event limit fails the poll instead of truncating history. PR lists request 25 entries per page. Each repository has a default and maximum limit of 401 page requests, including any terminal empty-page probe; the total event limit still applies across repositories. Each response is limited to 2,000,000 bytes and records/checkpoints to 32,000,000 bytes; retained encoded response history is limited to half the record cap. Excessive retained API history or rate use fails closed. Smaller pages reduce the size of individual responses but do not guarantee that a live poll fits these bounds. The checkpoint is read once and hashed from the same bytes that are parsed. Writes use a temporary file and atomic replacement. A selection remains pending; the prototype has no completion or retry executor and rejects completed checkpoint records. A future reviewed state transition must authenticate completion. A selected PR may have closed or changed: obtain fresh PR detail, revalidate the exact head and base, pick a separately reviewed clean control, and feed the resulting captured event to PR #160's resolver and source-first scan. The default-tip path has no compatible resolver yet. PR #160 is not part of this main-based prototype. Never mark a discovery record completed merely because it was selected.

The API listing is not atomic: updates during pagination can shift or omit entries. Polling snapshots also cannot see transient heads or intermediate default-branch commits between polls. Consequently the record is an inventory of returned identities, not a guarantee of every upstream event or a complete point-in-time snapshot. The queue retains previously observed pending identities, but persistence depends on the operator. Closed, superseded and stale events remain pending indefinitely and can exhaust the bound; there is no progress or completion transition. A same-key change in head provenance fails the poll for review even if the commit SHA is unchanged. Redirects, malformed links, page limits, rate exhaustion, malformed or inconsistent identities and API errors fail closed. Valid next links are checked against the same HTTPS API origin, repository and exact query parameters; short pages may still have a next link. A full page without a next link requires an additional empty-page check within the page bound. Link parsing accepts a conservative subset and rejects unsupported syntax; live GitHub compatibility has not been tested. No scheduled scan is enabled; measured full-corpus cost, immutable release lock, Gate 8 drill, durable checkpointing, event-resolution and alert ownership remain required before promotion.
