# LuCI base package-byte inventory

This separate, manual experiment implements the source-first [oracle](ORACLE.md) for LuCI `cb87fe60e1e2e052af36a93647f2264577829e0a`. The earlier `tools/installed-byte` two-file experiment remains unchanged. No run or package-byte claim follows from these scripts alone.

The Linux runner clones exact OpenWrt, LuCI and packages feed revisions into a new run directory, verifies the frozen oracle and source recipe hashes before toolchain work, captures inputs and timings, builds one `luci-base` IPK, retains the exact IPK and compares its bytes. The parser inventories all data and control entries without extracting them, rejecting unsafe paths, duplicate identities, unsupported member types or metadata, invalid sizes and trailers. Its intentionally strict tar subset can reject a legitimate new archive format; a rejection requires investigation, not an automatic relaxation. The comparator checks selected candidates, a required extensionless shell control, generated `version.uc`, source-prepared-staged-IPK hashes and modes, control metadata and unexpected Ucode-shaped members. Additional extensionless non-Ucode entries appear in the full archive receipt and remain unclassified.

Run local focused checks with `python3 -B -m unittest discover -s tools/luci-base-inventory -p 'test_*.py' -v` and `bash -n tools/luci-base-inventory/run.sh`. The workflow runs these checks for relevant pull requests. Its manual experiment is a costly, single-attempt build; freeze and independently review the exact code, source-first oracle, pins and inputs before dispatch. Retain the raw artifact, logs and failing attempts. Missing members, changed transforms or unsupported archive forms are failures or unresolved evidence, not evidence of absent security problems, installed root-image state or CodeQL coverage.
