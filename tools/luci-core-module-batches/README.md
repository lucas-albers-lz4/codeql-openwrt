# LuCI core module package batches

This is an offline contract prototype for OpenWrt #173. It starts from the independently reviewed, source-first inventory at `source-oracle.json` (SHA-256 `afa112d09dce539a3e51845cd0786938194cb8c8af7d4c67d9713361b83693a5`). That inventory pins LuCI `cb87fe60e1e2e052af36a93647f2264577829e0a` and consumer inventory #172. It predicts candidate paths from source and recipes; it is not package evidence.

The batch boundary is three separate packages: `luci-mod-status`, `luci-mod-network`, and `luci-mod-system`. `luci-mod-admin-full` is included only as a dependency collection when resolving the selected source feed; it is not a payload package in this comparison. The batch requires one frozen OpenWrt/LuCI/packages-feed source set and resolved config, serial builds, unique stage/IPK resolution, and a distinct retained IPK and receipt for each package. Every later build must recheck earlier stage and archive identity so stale output cannot be selected silently.

The source oracle marks one status `.ut`, three extensionless shell controls, and four ACL files (two status, one network, one system) for focused byte and route-boundary checks. It also inventories auxiliary root and htdocs files. Direct copies can be compared from source through prepared, staged and IPK bytes. The `.ut` substitution is verified against the pinned recipe before equality is asserted. If JS/CSS minification is enabled, source-to-output bytes remain unknown; if disabled, equality is expected. `luci-mod-status` compiles `luci-bwc`; its generated bytes and mode are unknown before the build and must be recorded as observations. Full archive parsing records data and control directory rows separately; exact stage/IPK agreement applies to every regular data and `CONTROL` file. Stage-directory modes are not compared because the archive may omit implicit directories. The parser rejects data members in the reserved `CONTROL` namespace. No derived record here establishes runtime operation, root-image installation, RPC authorization, markup semantics, extraction completeness or CodeQL coverage.

No package build or dispatch has been started from this worktree. The manual build stays gated on completion and reconciliation of the active app/service workflow, exact source/oracle review, and review of this implementation. Offline tests must exercise a complete synthetic package packet plus negative controls for missing/mismatched members, wrong modes, duplicate/unsafe archive entries, source/prepared/stage/IPK divergence, wrong control identity and ambiguous output resolution. CI runs only these offline tests on pull requests; it must not launch a build.
