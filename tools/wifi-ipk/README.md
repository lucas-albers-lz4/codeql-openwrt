# Draft manual wifi-scripts IPK experiment

This is an unexecuted experiment, not evidence of installed bytes or Gate 6 completion. A manual Linux dispatch builds two sequential, independent x86/64 core OpenWrt checkouts at `4e9642517b48bae612ff10fb72fb9199e559500e`. It freezes all final configuration except `CONFIG_WIFI_SCRIPTS_UCODE`, and fails if any other configuration differs. The source-first oracle is copied from the coverage ledger's `evidence/mvp-wifi-scripts-extraction-20261124/source-first-oracle.json`; its original selection hash and route correction remain in that file. The comparator checks the source Git blobs and working bytes, stage and actual IPK data, including the shell/Ucode collision. It inventories regular Ucode-looking IPK members and rejects nonregular `.uc`/`.ucode` members (stage-only extra members are outside this inventory): 17 in the enabled variant and seven common members in the disabled variant. It rejects duplicates, nonregular selected paths, missing or extra Ucode members, a wrong control identity, mismatched bytes and altered config.

The recipe's empty prepare step leaves the pinned core source as the build input; package staging and the IPK are independently read after the actual build. The script retains both exact archives, configs, source hashes, commands, statuses and GNU time measurements; failure or missing receipt is not a pass. It does not run a CodeQL extraction, install a root filesystem or establish runtime behavior. No Linux result is claimed. The pinned IPK control identity and build/config assumptions are fail-closed hypotheses that must be checked against a first Linux run; do not adjust them merely to manufacture a pass.

This is resource intensive: two full host-tool and cross-toolchain builds, sequentially, with separate download caches, may exceed hosted runner disk or the six-hour timeout. It needs case-sensitive Linux, a run root without spaces (OpenWrt rejects space-containing TOPDIR paths), network access, OpenWrt build prerequisites, sufficient disk and memory, and GNU time. The run records disk and memory before and after each variant preparation and build, including on failure, and compares both resolved configurations before bootstrap; no retry is automatic. Review the workflow revision before dispatch. Offline checks are `python3 -B -m unittest discover -s tools/wifi-ipk -p 'test_*.py' -v`, `bash -n tools/wifi-ipk/run.sh`, and `actionlint .github/workflows/wifi-ipk-manual.yml`. These do not build an IPK or authenticate a remote run.
